Windows 10 22H2 build 19045; adm = elevated Administrator token, std = local standard user. Per-area summaries and failing/skipped test lines only. Seconds are informational.

Determinism check: the whole non-dx corpus (47 areas, both modes) ran on fresh guests several times; per-test results and every printed line were compared between runs. Four sources of run-to-run variation were found and removed: a cancel-after-completion result in getaddrinfo_family (now accepts either legitimate outcome), a one-pass drain assumption in lift_07 (now drains until the notification arrives, bounded), and check counts that depended on a race outcome in async_select_messages and lift_07 (checks normalised so the count is fixed; a race-dependent note removed). After the fixes three consecutive runs of the three affected areas in both modes were byte-identical. All remaining skips repeat identically in every run: IPX not installed, event-object mode only (two lift_07 cases), the qos error-path and service-configuration cases, and, for the standard-user mode only, raw sockets and provider/service operations that need an elevated token.

The 15 x_* areas were run in both modes on fresh guests (no failures). x_stress_soak_bounded had its refused-connect loop cut from 100 to 4 rounds because each refusal costs about two seconds there. x_overlapped_matrix, x_raw_icmp_elevated, x_registered_io and x_select_poll_matrix were run in both modes with identical per-mode check counts across separate guests; the other x_* areas have a single run per mode so far.

The 6 gap_* areas ran in both modes and the 7 guarded dx_* areas ran in the elevated mode only (one run each, not repeated). dx_gap_02: three service-class cases skipped because registration was refused with WSAEHOSTUNREACH (10065) on the guest; dx_qos_misc_apis: one case skipped as only meaningful for a plain token. The dx areas were not run in the standard-user mode (they skip unless elevated).

Not verified: determinism across repeated guests for the gap_*, dx_* and most x_* areas (single run per mode), any Windows build other than 19045, any server SKU, IPv6-less or IPX-equipped guests. Headless Wine runs (hang/crash check only) completed for every non-dx area; results there are not evidence for or against an expectation.
